# Посібник дизайну ігор — уніфікація структури й візуалу

Складено на основі аналізу трьох еталонів (`mafia.html`, `draw.html`, `sudoku.html`) і повного репозиторію (~20 ігор + спільні `js/*`, `teli-style.css`, `game-header.css`).

Мета: **не уніфікувати вайб** (кожна гра має свою палітру й характер), а уніфікувати те, що є суто інженерним/структурним і зараз "заново винаходиться" в кожному файлі: заокруглення, банери-переходи, позиціонування шарів, чорні напівпрозорі підкладки й реальний блюр.

---

## 1. Дві незалежні ознаки замість трьох архетипів

Раніше тут був поділ на три архетипи (state-machine / simple game / game field) в одну вісь "складність". На практиці кілька ігор (`memology`, `draw`, `teli`) не лягали чисто в жодну категорію — вони одночасно і "прості" за кількістю фаз, і мають повноцінне ігрове поле. Замість трьох імен — **дві незалежні бінарні ознаки**. Кожна гра відповідає "так/ні" на кожну з них окремо, тому прикордонних випадків більше немає — є лише квадранти.

### 1.1. FSM / non-FSM

**Критерій (перевіряється по коду, не на око):** гра — **FSM**, якщо `state.phase` (чи еквівалент) керує **5 і більше** явно названих фаз, і хоча б частина переходів між ними супроводжується повноекранним банером-переходом (`.banner-screen`) і/або власним таймером на фазу. Якщо фаз менше 5, або переходи не мають банерної хореографії — гра **non-FSM**, незалежно від того, чи є в неї RTDB-кімната і лобі взагалі.

Це навмисно рахується по коду: полічи унікальні значення `case "..."` / `phase === "..."` у диспетчері рендера. Приклад підрахунку по репозиторію (реальні числа, не оцінка на око):

| Гра | Кількість фаз | FSM? |
|---|---|---|
| `mafia` | 15 | **так** |
| `quiplash` | 7 | **так** |
| `quiz` | 4 | ні |
| `teli` | 3 | ні |
| `spy` | 3 | ні |
| `memology` | 2 | ні |
| `draw` | 2 | ні |
| `poker` | 1 | ні |
| `snake`, `sudoku`, `2048`, `tetris`, `wordle`, `soliter`, `miner`, `whoami`, `crocodile`, `doodle` | 0 | ні |

Розрив між 15/7 і найближчим сусідом (4) достатньо великий, щоб не сперечатись про межу — на практиці FSM зараз тільки `mafia` і `quiplash`.

### 1.2. Gamefield / non-gamefield

**Критерій:** гра — **gamefield**, якщо основна взаємодія відбувається на постійній 2D-поверхні (canvas або сітка клітинок/карток), яку гравець безпосередньо й неперервно "чіпає" протягом раунду (малює, рухає фігуру, клікає клітинки/картки) — а не просто дивиться на список гравців/чат/картку ролі. Якщо основний UI — це списки, голосування, чат, картки-в-руці чи одноразовий reveal — гра **non-gamefield**, навіть якщо вона мультиплеєрна й має RTDB.

| Гра | Поле? | Gamefield? |
|---|---|---|
| `sudoku`, `tetris`, `2048`, `wordle`, `soliter`, `miner`, `snake` | сітка/canvas, соло | **так** |
| `draw`, `doodle` | canvas для малювання | **так** |
| `teli` | canvas (раунд малювання всередині гри) | **так** |
| `memology` | сітка карток, що гравець клікає | **так** |
| `mafia`, `quiplash`, `quiz`, `spy`, `poker`, `whoami`, `crocodile` | списки/голосування/чат/картка ролі, без постійного поля | ні |

`poker` — прикордонний на перший погляд (карти на столі), але тест той самий: гравець там не "чіпає" сам стіл (не тягає карти, не малює) — взаємодія це кнопки "чек/фолд/рейз" над станом, який просто відображається. Тому `poker` — non-gamefield.

### 1.3. Матриця

|  | **gamefield** | **non-gamefield** |
|---|---|---|
| **FSM** | *(поки що жодної гри — тримаємо клітинку про запас)* | `mafia`, `quiplash` |
| **non-FSM** | `draw`, `teli`, `memology`, `snake`, `sudoku`, `2048`, `tetris`, `wordle`, `soliter`, `miner`, `doodle` | `quiz`, `spy`, `poker`, `whoami`, `crocodile` |

Обидві ознаки навмисно **не** кажуть нічого про мережу (RTDB) — це третій, окремий факт, який далі впливає лише на те, які спільні `js/*`-модулі підключати (розділ 10), а не на візуальну класифікацію. Для довідки, хто з non-FSM/gamefield усе ж має RTDB-кімнату (`online-engine.js`): `draw`, `teli`, `memology`, **`snake`**. Решта gamefield-ігор (`sudoku`, `2048`, `tetris`, `wordle`, `soliter`, `miner`, `doodle`) — повністю локальні, без мережі. `snake` тут єдиний виняток у своєму квадранті — якщо береш його як приклад "чистого" gamefield, пам'ятай, що йому додатково потрібне мережеве підключення, якого в сусідів немає.

Це виключно **функціональна** класифікація. Вона не повинна впливати на візуальні токени нижче — вони спільні незалежно від FSM/gamefield.

## 2. Що уніфікуємо, що лишається вільним

**Уніфікуємо (однакові імена змінних, однакова логіка/розмітка в кожній грі):**
- шкала заокруглень (border-radius)
- система банерів / повноекранних оверлеїв-переходів
- позиціонування (page-контейнер, safe-area, шари z-index)
- підкладки: чорна напівпрозора "плашка" vs реальний блюр — коли яка

**Лишається вільним (навмисно різне за грою):**
- кольорова палітра (`--bg`, `--accent`, `--tile-bg` тощо) — значення різні, **імена змінних однакові**
- шрифтові пари (хоч Space Grotesk + Inter вже де-факто стандарт — лишити як базовий вибір, дозволити виняток типу `Special Elite` для мафії)
- ігрова механіка, форма ігрового поля

## 3. Базовий шаблон `:root`

Зараз кожна гра описує однакові за змістом токени під різними іменами (`--tile-bg` vs `--bg-tile` vs `--bg-panel`, `--text-light` vs `--text-primary`). Пропоную єдиний фіксований набір **імен**, кожна гра підставляє свої значення:

```css
:root {
  /* поверхні */
  --bg: #14161a;          /* фон сторінки */
  --surface-1: #1c1f2b;   /* картка/панель (було tile-bg / bg-panel) */
  --surface-2: #262a3a;   /* вкладений елемент на surface-1 (було tile-bg-2) */
  --line: rgba(255,255,255,0.08); /* межі/розділювачі */

  /* текст */
  --text: #f2f1ec;        /* було text-light / text-primary */
  --text-muted: #8d90a3;

  /* акценти (у кожної гри — свій вайб) */
  --accent: #d9b45c;
  --danger: #d97070;      /* було error / blood / spy-color — уніфікувати саме роль "негативний стан" */

  /* шрифти */
  --font-display: 'Space Grotesk', sans-serif;
  --font-body: 'Inter', sans-serif;

  /* --- структурні токени (однакові значення в УСІХ іграх, не тільки імена) --- */
  --radius-xs: 4px;
  --radius-sm: 8px;
  --radius-md: 14px;
  --radius-lg: 20px;
  --radius-pill: 999px;

  --scrim: rgba(0,0,0,0.31);        /* базова чорна напівпрозора підкладка — саме так конвертується #00000050, реальне значення з мафії */
  --scrim-strong: rgba(0,0,0,0.82); /* для модалок/паузи поверх активної гри */
  --blur-panel: 12px;               /* реальний блюр для "скляних" панелей */
  --blur-bg: 3px;                   /* легкий блюр для фонових зображень (day/night сцени) */
}
```

> Практично: `--radius-*`, `--scrim*`, `--blur-*` — це і є ті "стабільні назви змінних і логіки", про які йшлося. Решта токенів — стабільні **імена**, довільні **значення**.

## 4. Шкала заокруглень (border-radius)

У репозиторії зараз 18 різних значень radius без системи (2px…150px впереміш). З аналізу фактичного вжитку видно природні кластери — на них і будуємо шкалу:

| Токен | Значення | Де використовувати | Приклади з коду |
|---|---|---|---|
| `--radius-xs` | 4px | найдрібніші елементи: клітинки поля, клавіші | `.cell`, `.key` |
| `--radius-sm` | 8px | маленькі кнопки/чіпи/теги всередині картки | `.mode-btn`, `.num-btn`, `.tag` |
| `--radius-md` | 14px | **дефолт для карток, панелей, списків, інпутів** | `.card`, `.panel`, `.chat-log`, `.host-panel` |
| `--radius-lg` | 20px | великі кнопки/таби, основні touch-цілі | `.primary-btn`, `.diff-tab`, `.action-row` |
| `--radius-pill` | 999px | бейджі, індикатори прогресу, круглі кнопки-таби | `.badge-turn`, `.player-chip`, `.final-bar-track` |
| `50%` | — | аватари, круглі іконки-кнопки (лишається сирим значенням, не токеном) | `.mini-avatar`, `.pause-btn` |

Правило: якщо новий елемент не підпадає явно під один із кластерів — бери найближчий менший (краще трохи гостріше, ніж вигадувати нове число).

## 5. Шкала z-index (шари)

Зараз z-index розкидані хаотично: `20, 22, 90, 95, 96, 100, 500, 900, 999, 9000, 9997, 9999`. Це працює тільки тому, що оверлеї рідко перетинаються в одній грі, але унеможливлює перевикористання компонента між іграми. Пропонована фіксована шкала:

```css
:root {
  --z-bg-scene: 0;      /* фонові декоративні шари (bg-scene, scene-bg) */
  --z-content: 1;       /* звичайний контент сторінки */
  --z-sticky: 10;        /* липкі елементи (top-bar, game-header--fixed) */
  --z-banner: 20;        /* банери переходів фаз (banner-screen) */
  --z-sidebar: 90;       /* бокові панелі + їх сірий scrim (90/91) */
  --z-modal: 100;        /* модалки, fullscreen-reveal */
  --z-pause: 500;        /* оверлей паузи — завжди понад усім активним */
  --z-fx: 900;           /* короткі повноекранні ефекти (супер-сміхлисток тощо) */
  --z-toast: 999;        /* системні тости/нотифікації */
}
```

Мапінг на існуюче: `pausedOverlay`/`pause-overlay` → `--z-pause`; `sidebar-overlay`/`sidebar` → `--z-sidebar` (+1); `modal-overlay`, `fullscreen-reveal`, `gen-overlay`, `feed-overlay` → `--z-modal`; `banner-screen` → `--z-banner`. Значення на кшталт `9997`/`9999` в snake/wordle/soliter — прибрати на користь `--z-modal`/`--z-toast`.

## 6. Підкладки: чорна плашка vs реальний блюр

Це найбільш хаотична зона зараз: opacity чорного фону скаче `0.35–0.9` без причини, а `backdrop-filter` застосований лише у 3 місцях з ~66 файлів. Пропонується чітко розділити на **два патерни** з двома готовими класами.

### 6.1. `.panel-on-image` — плоска чорна плашка (дешево, для тексту поверх картинки)
Використовуй, коли елемент лежить поверх фонового зображення/градієнта і треба лише читабельність тексту, без "скляного" ефекту (як `#00000050` в мафії на `h2`, `.info-bar`, `.last-words-box`):

```css
.panel-on-image {
  background: var(--scrim); /* rgba(0,0,0,0.31) — саме так конвертується #00000050 (0x50/255≈0.31), а не 0.5 */
}
```

Мафія використовує цей патерн як смугу на всю ширину, від краю до краю, БЕЗ заокруглення — тому тут навмисно немає `border-radius`. Якщо в конкретній грі потрібна саме "картка" з таким фоном (не смуга на всю ширину), додай модифікатор:

```css
.panel-on-image--card { border-radius: var(--radius-md); }
```

Не змішуй два варіанти в одному класі — full-bleed смуга і картка з відступами повинні лишатись різними, свідомими рішеннями, а не одним дефолтом, який десь підходить, а десь ні.

### 6.2. `.glass-panel` — реальний блюр (для елементів поверх живого/рухливого контенту)
Використовуй, коли під елементом активна гра/канвас/анімація і хочеться відчуття скла (як `game-header.css`, `.top-bar::before` в index.html):

```css
.glass-panel {
  background: var(--scrim); /* rgba(0,0,0,0.31) = #00000050 */
  backdrop-filter: blur(var(--blur-panel));
  -webkit-backdrop-filter: blur(var(--blur-panel));
  border-radius: var(--radius-md);
}
```

**Правило вибору:** якщо позаду статична картинка/градієнт → `.panel-on-image` (дешевше, легше для мобільних GPU). Якщо позаду canvas/сітка/анімація, яку користувач бачить "крізь" елемент (хедер гри, липка панель) → `.glass-panel`.

### 6.3. Модальні/паузові scrim
Для повноекранних затемнень під модалкою/паузою — окремий, сильніший рівень:
```css
.scrim-modal {
  position: fixed; inset: 0;
  background: var(--scrim-strong); /* rgba(0,0,0,0.82) */
  z-index: var(--z-modal); /* або --z-pause для паузи */
  display: flex; align-items: center; justify-content: center;
}
```
Замінює зоопарк `rgba(0,0,0,0.6/0.7/0.75/0.88)`, який зараз розкиданий по `memology.html`, `snake.html`, `wordle.html`, `quiplash.html`.

## 7. Банери-переходи (`.banner-screen`)

Патерн з `mafia.html` (banner_night/banner_day/win/lose) — єдиний повноцінний приклад повноекранного банера-переходу в репозиторії. Варто зробити його спільним компонентом для будь-якої гри типу **state-machine**, яка має драматичні переходи між фазами (не лише мафія — підійде і для quiplash-подібних "суперраундів").

```css
.banner-screen {
  position: fixed; inset: 0;
  z-index: var(--z-banner);
  display: flex; align-items: center; justify-content: center;
  background-size: cover; background-position: center;
  animation: bannerFade 0.4s ease;
}
.banner-caption {
  font-family: var(--font-display);
  font-size: 30px; text-align: center; color: var(--text);
  text-shadow: 0 3px 10px rgba(0,0,0,0.8);
  padding: 20px; border-radius: var(--radius-md);
  background: var(--scrim);
}
@keyframes bannerFade { from { opacity: 0; } to { opacity: 1; } }
```
Кожна гра задає лише `background-color`/`background-image` для своїх конкретних `.banner-screen.<назва-фази>` — сама структура (позиція, анімація, підпис) береться з цього блоку без змін.

## 8. Позиціонування: контракт `.page`

Усі три еталони (і більшість ігор) вже сходяться на схожій структурі, але з дрібними розбіжностями (max-width 430 vs 480, різний overflow). Фіксуємо єдиний контракт:

```css
* { box-sizing: border-box; -webkit-tap-highlight-color: transparent;
    user-select: none; -webkit-user-select: none; -webkit-touch-callout: none; }

html, body {
  margin: 0; padding: 0; min-height: 100dvh;
  background: var(--bg); color: var(--text);
  font-family: var(--font-body);
  overflow-x: hidden; touch-action: manipulation;
}

.page {
  max-width: 480px;         /* єдине значення для всіх ігор, не 430/480 впереміш */
  margin: 0 auto;
  min-height: 100dvh;
  position: relative;
  z-index: 0;                /* ОБОВ'ЯЗКОВО, не auto — див. попередження нижче */
  display: flex; flex-direction: column;
  overflow: hidden;          /* ховає запас transform:scale() фонового шару, див. нижче */
  padding-bottom: env(safe-area-inset-bottom);
}

.hidden { display: none !important; }
```

Фонове зображення (day/night/scene) — завжди окремим шаром `::before` з `z-index: var(--z-bg-scene)`, а не напряму на `.page` (як вже правильно зроблено в мафії) — це дає можливість блюрити тло (`--blur-bg`), не чіпаючи контент.

> **Пастка, на яку вже наступили в мафії:** якщо `::before`-шар використовує від'ємний `z-index` (напр. `-1`, а не `0`) для гарантованого розташування "позаду всього контенту" — `.page` **обов'язково** повинен мати власний явний `z-index` (не `auto`). Інакше `.page` не створює власний stacking context, і від'ємний `z-index` дочірнього `::before` "втікає" на рівень вище й малюється ЗА фоном `body`/`html` — тло зникає повністю, навіть якщо картинка/градієнт коректно підвантажились. Саме тому в контракті вище вже стоїть `z-index: 0`. Якщо замість цього фоновий шар отримує `z-index: 0` (як `var(--z-bg-scene)` за шкалою з розділу 5) — ризик менший, але однаково безпечніше завжди тримати `.page` явно поза `z-index: auto`.
>
> Другий наслідок того ж прийому: якщо `::before` ще й трохи більший за контейнер (`transform: scale(1.05–1.1)`, щоб розмиття не показувало різкий кант по краях), на `.page` потрібен `overflow: hidden` — інакше цей запас вилазить за межі екрана горизонтально. Обидва рядки вже включені в контракт вище.

Повноекранні оверлеї (`fullscreen-reveal`, `pause-overlay`, модалки) — завжди `position: fixed; inset: 0;`, ніколи `position: absolute` відносно `.page` — інакше вони не покривають екран, якщо `.page` не на всю висоту.

## 9. Іменування (naming conventions)

Щоб код було легко переносити між іграми copy-paste-ем, тримайся однакових суфіксів для однакових ролей:

- `-overlay` — контейнер, що затемнює/блокує задній план (`sidebar-overlay`, `modal-overlay`)
- `-panel` / `-card` — картка контенту (панель — прямокутна, картка — з наголосом на вміст)
- `-btn` — будь-яка кнопка; модифікатор ролі через клас-міксин: `primary-btn`, `secondary-btn`, `small-btn` (не вигадувати нові базові назви кнопок під кожну гру)
- `-chip` — маленький інформаційний блок в рядок (гравець, статус)
- `-badge` — ще менший, суто лейбл/статус без інтерактивності
- `phase-*` / `view-*` — модифікатори стану для диспетчера станів (уже конвенція в mafia/draw — поширити і на нові state-machine ігри)

## 10. Чекліст для нової гри

1. Підключити спільні токени (`:root` з розділу 3) — скопіювати блок структурних токенів **без змін**, підставити лише кольори під вайб гри.
2. Визначити дві ознаки — FSM/non-FSM і gamefield/non-gamefield (розділ 1) — та окремо перевірити, чи потрібна RTDB-кімната. Разом вони визначають, які спільні `js/*`-модулі підключати: RTDB-ігри (FSM або non-FSM з мережею) — `online-engine.js` + `room-code-ui.js`; повністю локальні — `game-header.js` + `login.js` + `score-connect.js`.
3. Заокруглення — брати лише з `--radius-*`, не вигадувати нових чисел.
4. Оверлеї — класифікувати кожен як `.panel-on-image`, `.glass-panel` або `.scrim-modal`, виставити `z-index` лише з фіксованої шкали (розділ 5).
5. Якщо є драматичні переходи фаз — використати `.banner-screen` з розділу 7 замість написання власного з нуля.
6. `.page` — контракт з розділу 8, фон — окремим `::before`.
7. Перевірити safe-area (notch/home-indicator) на фіксованих елементах (`env(safe-area-inset-*)`).

### Що свідомо не чіпаємо
Кольорові палітри, шрифтові акценти під конкретний вайб (напр. `Special Elite` для мафії), ігрову логіку та структуру диспетчера — усе це має лишатись гнучким під кожну гру.
